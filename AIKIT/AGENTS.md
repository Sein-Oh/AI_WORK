# 전역 지침 (사내 PC, OpenCode, C:\AIKIT 프로젝트)

이 파일은 `C:\AIKIT`을 프로젝트로 연 대화(`web.bat`, `C:\AIKIT`에서 실행한 `opencode`)에서만 읽힌다. 그 대화의 모든 일에 적용한다.

## 1. 언어와 표기
1. 답변, 설명, 코드 주석, 새로 만드는 문서는 모두 한국어로 쓴다. 명령어, 파일 경로, 옵션 이름은 원문 그대로 쓴다.
2. 이모지와 장식 기호(화살표 모양 문자, 체크 표시, 별)를 쓰지 않는다. 수식 표기(`$...$`, `$\rightarrow$`, `$R^2$`)도 쓰지 않고 `->`, `R2`처럼 글자로 쓴다. 화살표는 `->`, 표시는 `[OK]`, `[주의]`처럼 글자로 쓴다. 도구 결과의 `->`도 그대로 옮긴다.

## 2. 이 PC 환경
- Windows 11, 셸은 PowerShell이다.
- **폐쇄망이다. 인터넷이 전혀 안 된다.** 웹 검색·웹 페이지 열기 도구(`websearch`, `webfetch`), 내려받기(`curl`, `Invoke-WebRequest`, `git clone`), `pip install`을
  시도하지 않는다 (실패하고 시간만 쓴다). 모르는 것은 이 PC의 파일(이 지침, SKILL.md, 사용자가 준 문서)과 아는 지식으로만 답하고,
  그래도 모르면 "폐쇄망이라 인터넷에서 찾아볼 수 없습니다"라고 알린다. 필요한 패키지가 없으면 사용자에게 알리고 멈춘다.
- **결과 파일 위치**: 사용자가 경로를 주면 그 경로에 둔다. 경로를 주지 않으면 파일을 대상으로 한 작업의 결과는 대상 파일과 같은 폴더에,
  대상 파일이 없는 작업(메일, 저장한 적 없는 문서, 여러 파일 검색)의 결과는 `C:\AIKIT\data`에 둔다. 도구는 `--save`를 생략하거나 이름만 주면
  이 규칙대로 저장하므로 경로를 지어 붙이지 않는다. 저장된 곳은 결과 JSON의 `output_file`이다.
- 파이썬은 `python` 명령으로 실행한다 (`C:\AIKIT\python`, PATH에 등록됨). `py`, `python3`, `pip`는 쓰지 않는다.
- 셸 명령은 한글이 깨지지 않게 **항상 아래 줄을 맨 앞에 붙여** 한 줄로 실행한다.
  ```powershell
  $env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'; [Console]::OutputEncoding=[Text.Encoding]::UTF8; python "<스크립트>" <인자>
  ```
- PowerShell 인자 규칙:
  1. 경로와 값은 큰따옴표 `"..."`로 감싼다.
  2. 값에 `$` 또는 `` ` ``가 들어 있으면 작은따옴표 `'...'`로 감싼다. 큰따옴표 안의 `$`는 변수로 바뀐다 (예: 엑셀 수식 `'=$A$1*2'`).
  3. 큰따옴표가 들어간 값(JSON 등)과 여러 줄 글은 인자로 넣지 않는다. 파일 쓰기 도구로 UTF-8 파일을 만든 뒤 그 경로를 넘긴다.

1. 위 작업은 스킬 명령으로 한다. 스킬로 되는 일을 pandas, openpyxl, python-docx, win32com 등으로 다시 짜지 않는다 (예외: 스킬이 4장대로 해도 또 실패하면 8번).
   파일 내용이나 행 수 확인도 스킬로 한다: 엑셀/CSV는 `excel.py read --target "<파일>"`, 그 밖의 문서는 `reader.py read --file "<파일>"`.
   파일 찾기에 파일이 안 나와도 사용자가 준 경로로 스킬 명령을 그대로 실행한다 (파일이 없으면 도구가 알려 준다).
   위 표와 각 SKILL.md 명령 표에 없는 일은 8장대로 한다 (8장의 "나. 하지 않는 일"은 파이썬으로도 하지 않는다).
2. 도구는 `C:\AIKIT\ml-kit`, `C:\AIKIT\office-cli`, `C:\AIKIT\pandas-kit`에만 있다 (다른 폴더의 경로, 예: `C:\AIKIT\dev`는 데이터 위치일 뿐이다). SKILL.md의 명령 경로를 그대로 쓴다. 한 요청이 두 작업에 걸치면(예: 메일 첨부를 검색) 두 스킬을 차례로 쓴다.
3. 해당 스킬의 SKILL.md를 먼저 읽고, 템플릿 명령을 그대로 쓴다. `<...>` 부분만 바꾸고 옵션이나 명령 이름을 지어내지 않는다.
   스킬 불러오기가 실패하면 아래 파일을 읽기 도구로 직접 읽는다. 읽기 전에는 도구 명령을 실행하지 않는다.
   `C:\AIKIT\.opencode\skills\<스킬 이름>\SKILL.md` (예: `C:\AIKIT\.opencode\skills\excel-kit\SKILL.md`, `C:\AIKIT\.opencode\skills\ml-train\SKILL.md`)
4. 도구는 항상 `python "<스크립트 전체 경로>" <명령> ...`으로 실행한다. `.py` 파일 경로만 실행하면 편집기가 열리고 결과가 없다.
   실행하는 .py는 SKILL.md 표에 있는 것뿐이고, 경로는 SKILL.md에 적힌 전체 경로를 한 글자도 바꾸지 않고 쓴다
   (`C:\AIKIT\office-cli\excel.py`, `C:\AIKIT\ml-kit\ml_train.py`처럼 도구 폴더 바로 아래. 데이터 보기는 `excel.py read`, 한 건 예측은 `ml_predict.py --input`).
5. 사용자가 요청한 일의 명령은 묻지 않고 바로 실행한다. 명령을 답변에 적어 보여 주기만 하고 끝내지 않는다. 먼저 묻는 것은 넷뿐이다: `confirm_commands`(6번), 5장의 일(삭제·덮어쓰기·발송·새 시트), 도구가 `[후보]`·`needs_user_decision`으로 멈춘 때(4장), 사용자가 넣으라고 하지 않은 업무 판단(규격과 맞는지, 두 판에서 무엇이 바뀌었는지, 검토 의견)을 문서에 넣으려 할 때. 판단은 도구가 하지 않는다: 근거(값, `evidence`)와 함께 판단을 먼저 보여 주고 "예"를 받은 뒤 메모·서식으로 넣는다. 사용자가 이번 요청에서 넣으라고 했으면(예: "판정은 메모로 달아줘") 묻지 않고 넣은 뒤, 판정과 근거를 함께 알리고 되돌리기는 `python "C:\AIKIT\office-cli\office.py" undo`라고 알린다.
   명령은 1번만 실행한다. 출력의 **마지막 1줄 JSON**만 읽는다. `[PROGRESS]`, `[INFO]`, `[WARN]` 줄은 무시한다.
   출력을 `python -c`, `findstr`, 파일 저장으로 다시 풀지 않는다. 명령 뒤에 `| tail`, `| head`, `| python ...`을 붙이지 않는다 (출력을 그대로 읽는다).
6. JSON에 `next_commands`가 있으면 다음 단계는 그 `command`를 글자 그대로 실행한다(작은따옴표 `'...'`와 `\"`도 바꾸지 않는다, `needs_input: true`이면 `<...>`만 사용자가 준 값(파일이면 경로)으로 바꾼다). 명령을 새로 만들지 않는다.
   예외: `confirm_commands`(메일 발송, 미리보기 뒤 실제 변경, 다른 문서에 넣기)는 바로 실행하지 않는다. 무엇을 할지(받는 사람·제목, `planned`)를
   사용자에게 보여 주고 "예"를 받은 뒤에만 그 `command`를 글자 그대로 1번 실행한다. 사용자가 이번 요청에서 이미
   "묻지 말고 끝까지" 하라고 했으면 다시 묻지 않는다. 단 `"destructive": true`인 항목(덮어쓰기·삭제·메일 발송, 5장)은 그래도 늘 묻는다.
7. 파일 경로, 타겟 컬럼처럼 작업에 꼭 필요한 값을 모르면 실행 전에 사용자에게 묻는다.
8. 도구 코드(`C:\AIKIT\ml-kit`, `C:\AIKIT\office-cli`, `C:\AIKIT\pandas-kit` 아래 .py 파일)는 사용자가 코드를 열어 보라고 직접 요청할 때만 읽고, 고치지 않는다.
   스킬 명령 표에 없는 일이면 8장대로 한다. 스킬 명령이 `STOP_RETRY:`·`ERROR:`로 멈추면 먼저 4장대로 한다 (`[추천]` 1번 실행, `[후보]`·`needs_user_decision`·시트 보호·파일 없음은 사용자에게 묻기).
   4장대로 해도 같은 일이 또 실패하면(`ERROR:`, 또는 `[추천]`까지 실패) 그때는 파이썬으로 해도 된다: "도구로 처리하지 못해 파이썬으로 직접 처리합니다"라고 1줄 알리고 8장 1~6번대로.
   단 사용자에게 물어야 하는 일(위 묻기, 5장의 일)은 파이썬으로 돌아가지 않고 묻는다. `error_type: not_supported`(도구로 하지 않는 일)는 파이썬으로도 하지 않는다 (8장 나).

## 4. 결과 처리 (agent_directive의 첫 단어)
| 첫 단어 | 할 일 |
|---|---|
| `VERIFIED:` | 성공. `preview`를 알리고 끝낸다. 같은 명령을 다시 실행하거나 결과를 다시 열어 보지 않는다. `confirm_commands`가 있으면 3장 6번대로 사용자에게 묻는다. |
| `UNVERIFIED:` | 실행은 됐지만 도구가 결과를 확인하지 못했다. 다시 실행하지 않고 `unverified` 내용을 그대로 알린다. |
| `CONTINUE:` | 아직 끝나지 않았다 (명령 시간 제한 때문에 도구가 나눠서 진행, 한 일은 저장됨). 사용자에게 묻지 말고 `next_commands[0]`의 `command`를 그대로 다시 실행한다. `CONTINUE:`가 아닌 결과가 나올 때까지 반복한다 (느린 PC에서는 100번 넘게 걸릴 수 있음). 횟수는 세지 않는다: 끝나지 않을 것 같으면 도구가 `STOP_RETRY:`로 멈춘다. |
| `STOP_RETRY:` + message에 `[추천]` | `[추천]` 뒤의 명령을 글자 그대로 **1번만** 실행한다. 또 실패하면 message를 그대로 알린다 (그 뒤는 3장 8번). |
| `STOP_RETRY:` + message에 `[후보]` | 다시 실행하지 않는다. `[후보]` 목록을 보여 주고 사용자가 고르게 한다 (후보가 하나여도 묻는다). 사용자가 고른 번호의 `confirm_commands`(1번 = `confirm_commands[0]`)를 글자 그대로 1번 실행한다. `confirm_commands`가 없으면 명령에서 그 값만 고른 값으로 바꿔 1번 실행한다. |
| `STOP_RETRY:` (위 둘 없음) | 다시 실행하지 않는다. message를 그대로 알린다. `error_type`이 `needs_user_decision`이면 사용자에게 묻고, 원할 때만 `confirm_commands`(번호가 있으면 고른 번호) 또는 `next_commands[0]`의 command를 그대로 1번 실행한다 (둘 다 없으면 directive가 말한 옵션을 붙여 1번, 5장). |
| `ERROR:` | 다시 실행하지 않는다. message를 그대로 알린다 (그 뒤는 3장 8번). |

- JSON에 `recovered`가 있으면 (예: 파일이 열려 있어 새 이름으로 저장) 그 문장을 그대로 알린다. `warnings`가 있으면 함께 알린다.
- `error_type`이 `missing_library`이면 `install_command`를 사용자에게 전달만 하고 직접 실행하지 않는다.
- `error_type`이 `elevated_process`이면 다시 실행하지 않는다. 관리자 권한 창에서 실행 중이라 사용자가 연 문서가 안 보이니, 관리자가 아닌 일반 PowerShell 창에서 OpenCode를 다시 실행하라고 알린다.
- 문서 검색 결과의 `match_mode`가 `number`(숫자 값만 같은 곳, 부호·대시가 다른 숫자 포함), `partial`, `fuzzy`이면 정확히 일치한 곳은 0건(`count: 0`)이고 `candidates`는 비슷한 곳일 뿐이다. 근거로 쓰지 말고 사용자에게 확인받는다. `exact_mixed`이면 `matches` 중 `literal: false`(표기가 다른 곳, 부호·단위가 다를 수 있음)는 근거로 확정하지 말고 실제 글을 보여 주고 확인받는다(`snippet`에서 `**`는 글자 그대로 맞은 곳, `[[ ]]`는 표기가 다른 곳). 숫자를 찾은 결과를 알릴 때는 `snippet`의 앞뒤(부호, 범위 `~`, 이하/이상)를 그대로 함께 전달한다(`VERIFIED`는 그 글자가 그 자리에 있다는 뜻이고 문맥의 뜻은 판정하지 않음).
- `truncated`가 true이면 결과 일부만 받은 것이다. 전체 결과가 있는 곳(`full_result_file` 또는 `output_file`)을 알리거나, 이어 보기가 필요하면 `next_commands`를 쓴다.
- `error_type`이 `sheet_protected`이면 보호를 풀거나 암호를 묻지 않는다. message를 그대로 알리고, 사용자가 [편집 사용]을 누르거나 보호를 푼 뒤 같은 명령을 1번 다시 실행하거나 사용자가 고른 `[후보]` 칸에 쓴다.
- `error_type`이 `drm_or_dialog`이면 사용자에게 그 문서를 직접 열어 두라고 알리고, 열었다고 하면 `next_commands[0]`을 1번 실행한다.
- 메일은 가장 최근 목록·검색·대화(thread) 결과의 짧은 `id`(`--id 3`)로 고른다. 예전 목록의 번호를 다시 쓰지 않는다.
- 여러 칸이나 양식을 채우거나 여러 칸에 서식을 줄 때는 칸마다 명령을 따로 실행하지 않는다. `excel.py write --cells ...`, `excel.py style --range "B2;D5;F7" ...` 또는 `word.py fill --target "<양식.docx>" --slots ...` 한 번으로 한다 (양식 문서는 `--target`, 값은 `--slots`).
  칸이 어디인지 먼저 계산해야 하면(예: 행마다 E열과 가장 차이 나는 칸) `excel.py read`로 한 번 읽고 칸 목록을 정한 뒤 명령 한 번에 모두 넣는다. 칸·행마다 명령을 되풀이하지 않는다 (Office를 매번 다시 잡아 느리다).
- 학습에서 행을 빼거나 일부 행만 학습해 달라고 하면 데이터 파일을 고치지 않는다. ml-dataset 스킬로 새 데이터셋 파일을 만들고 그 파일로 학습한다.

## 5. 사용자 승인이 필요한 일
아래는 사용자가 이번 대화에서 분명히 요청했을 때만 한다. 실행 전에 대상(파일 경로, 시트 이름 등)을 보여 주고 "진행할까요?"라고 물어 "예"를 받는다.
- 파일·폴더 삭제 (`Remove-Item`, `del` 포함)
- 기존 파일 덮어쓰기 (`--overwrite` 포함)
- 메일 발송 (`outlook.py send`, `confirm_commands`로만 받음)
- 시트·슬라이드 삭제, 문서 내용 전체 지우기
- 사용자가 말하지 않은 새 시트·새 파일 만들기 (`--new-sheet` 포함. 8장의 스크립트와 요청한 결과를 담는 새 파일은 묻지 않는다). 사용자가 "Sheet9에 써줘"라고 해도 Sheet9가 없으면 먼저 만들지 물어본다.

도구 결과 message가 위 옵션을 붙이라고 안내해도, 사용자에게 먼저 묻는다. `confirm_commands`에서 이런 명령은 `"destructive": true`로 표시된다(3장 6번).

## 6. 보고
- 무엇을 했는지 1~2문장과 사용자에게 필요한 값만 알린다.
- 꾸밈 없이 글로 쓴다: 제목·목록 앞에 그림 문자를 붙이지 않고, `$R^2$`·`$\rightarrow$` 같은 수식 표기 대신 `R2`, `->`로 쓴다 (1장 2번).
  예: `학습을 마쳤습니다. 평균 R2 0.92, 생산효율 R2 0.80(개선 필요). 학습에서 뺀 행 16개. 결과 폴더: <도구가 준 경로>`
- 파일 경로는 결과 JSON의 값을 바꾸지 않고 그대로 1번만 쓴다. `file:///` 링크로 바꾸거나 `\\`를 `/`로 고치지 않는다.
- 파일이 여러 개면 폴더 경로 1번과 파일 이름 목록으로 쓴다.
- JSON 전체나 긴 목록을 답변에 다시 붙이지 않는다. `preview`와 필요한 값만 쓴다.
- 실패 원인을 추측해 지어내지 않는다. message를 그대로 전달한다.

## 7. 긴 대화
- 같은 스킬의 SKILL.md는 한 대화에서 1번만 읽는다. 이미 읽었으면 다시 읽지 않는다.
- 같은 파일을 반복해서 열어 보지 않는다. 도구 출력은 마지막 1줄 JSON만 본다.
- 작업 하나가 끝났고 다음 요청이 다른 파일이나 다른 주제면, "새 대화(/new)에서 이어 가면 더 정확합니다"라고 1번 안내한다.

## 8. 스킬로 안 되는 일
도구에 없는 일 중 아래 둘은 따로 다룬다. 어느 것이든 먼저 "도구에 없는 기능이라 파이썬으로 직접 처리합니다"(나는 "도구로 하지 않는 일입니다")라고 1줄 알린다.

가. **확인 뒤 하는 일** (열린 문서를 바꿈, 도구의 되돌리기 대상이 아님): 변경 내용 수락·거부, 피벗 테이블, 데이터 유효성, 기존 차트 고치기.
   실행 전에 무엇을 바꿀지(문서, 시트, 범위, 바꿀 내용)와 "바꾼 뒤에는 되돌리기가 안 될 수 있음"을 보여 주고 "진행할까요?"로 "예"를 받는다.
   바꾼 뒤 저장하지 않고 사용자에게 확인하고 저장하라고 알린다.
나. **하지 않는 일** (되돌릴 수 없거나 다른 사람에게 감): 스킬로도 파이썬으로도 하지 않고 직접 하는 곳만 알린다 (도구 결과 `error_type: not_supported`도 같음).

| 하지 않는 일 | 사용자에게 알릴 직접 하는 곳 |
|---|---|
| 인쇄 (설정 포함) | 그 앱의 파일 > 인쇄 |
| 회의 요청(참석자 초대) | Outlook 일정 > 새 모임 |
| 메일 이동·분류·플래그 | Outlook에서 직접 |
| 반복 일정·회의(참석자가 있는 일정) 지우기 | Outlook 일정에서 직접 |

나에 없고 3장 표와 각 SKILL.md 명령 표에도 없는 일(예: 여러 파일 합치기, 그래프 그림 파일, 통계 계산, 글 정리·변환)은
LLM이 아는 방법으로 파이썬 스크립트를 짜서 한다 (가의 일은 확인을 받은 뒤).
1. 3장 표와 해당 SKILL.md 명령 표에 있는 일은 먼저 스킬로 한다. 표에 없을 때는 "도구에 없는 기능이라 파이썬으로 직접 처리합니다", 스킬이 4장대로 해도 또 실패했을 때는 "도구로 처리하지 못해 파이썬으로 직접 처리합니다"라고 1줄 알리고 진행한다 (3장 8번).
2. 스크립트는 파일 쓰기 도구로 `C:\AIKIT\data\scripts\<짧은 영문 이름>.py`(UTF-8)에 만들고, 2장의 인코딩 줄을 붙여 `python "C:\AIKIT\data\scripts\<이름>.py"`로 실행한다.
   `python -c "..."`로 바로 실행해도 되지만, 실패하면 `python -c`로 다시 하지 말고 위처럼 파일로 만들어 실행한다 (PowerShell에서 따옴표와 한글이 깨진다). `python -`(표준 입력)는 쓰지 않는다. 스크립트는 이 폴더에만 만든다.
3. 설치된 라이브러리를 쓴다: pandas, numpy, scipy, scikit-learn, openpyxl, python-docx, python-pptx, matplotlib, seaborn, pymupdf, pywin32(win32com) 등.
   설치(`pip install`)는 하지 않는다. import가 실패하면 그 이름을 알리고 멈춘다.
4. 원본 파일은 고치지 않는다 (예외: 가의 일은 "예"를 받은 뒤 열린 문서만 바꾸고 저장하지 않는다). 결과는 2장 "결과 파일 위치"대로 원본 옆에 새 이름(예: `<원본>_집계.xlsx`)으로, 원본 파일이 없으면 `C:\AIKIT\data`에 저장한다. 덮어쓰기·삭제는 5장대로 먼저 묻는다.
   스크립트 끝에서 결과 파일 경로와 짧은 요약(행 수, 합계 등)을 print하고, 그 출력으로 결과를 알린다.
5. 스크립트가 실패하면 오류를 보고 고쳐 다시 실행하는 것은 방식(파일, `python -c`)과 상관없이 모두 합쳐 2번까지다 (처음 1번과 합쳐 3번). 그래도 실패하면 마지막 오류 줄을 그대로 알리고 멈춘다.
6. 열린 Office 문서(win32com)를 다룰 때:
   - 값 쓰기·서식·차트·메모처럼 스킬에 있는 일은 스킬 명령으로 한다. 스크립트는 스킬에 없는 부분만 한다.
   - 스크립트 하나에서 문서를 1번 잡고(`win32com.client.GetActiveObject("Excel.Application")` 등) 할 일을 모두 한다. 칸·행·슬라이드마다 스크립트나 명령을 따로 실행하지 않는다.
   - 범위 값은 2차원 배열로 한 번에 읽고 쓴다 (`v = rng.Value`, `rng.Value = rows`). 반복문 안에서 칸 하나씩 COM을 부르지 않는다 (칸마다 부르면 수백 배 느리다).
   - 사용자가 연 Office를 닫지(`Quit`) 않고, 사용자 문서를 저장하는 것은 5장대로 먼저 묻는다.

## 9. 지침과 스킬 파일 위치 (물어보면 아래를 그대로 알린다)
사용자가 "지침 어디 있어", "스킬 경로 알려줘"처럼 물으면 파일을 찾거나 열어 보지 말고 아래 표를 그대로 알린다.
우리 도구·지침·스킬은 `C:\AIKIT`을 OpenCode 프로젝트로 열 때만 쓰인다. 아래 파일을 복사하지 않고 그 자리에서 읽는다.
사내 LLM 설정과 셸·권한·폐쇄망 잠금은 모든 프로젝트에 적용되는 OpenCode 전역 설정(`%USERPROFILE%\.config\opencode`)에 있다.

| 무엇 | 파일 (고칠 때도 이것) |

## 10. 조합 스킬 만들기 (사용자가 요청할 때만)
사용자가 기본 스킬을 이어 쓰는 자기 스킬(예: 규격 대조, 주간 보고)을 만들어 달라고 하면 아래대로 SKILL.md를 쓴다. 쓰기 전에 내용을 보여 주고 "예"를 받는다 (9장).
1. 위치는 `C:\AIKIT\.opencode\skills\<이름>\SKILL.md` (이름은 소문자·숫자·하이픈, frontmatter `name`은 폴더 이름과 같게, `description`에 언제 쓰는지). 8KB 이하. 스크립트가 필요하면 그 폴더의 `scripts\`에 둔다.
2. 단계마다 기본 스킬 명령 표의 전체 명령(`python "C:\AIKIT\office-cli\<파일>.py" ...`)을 그대로 적는다. 옵션을 지어내지 않고, 도구로 되는 일을 파이썬으로 다시 짜지 않는다.
3. 앞 단계 결과 JSON의 파일 경로(`output_file`, `formats_file` 등)를 다음 명령의 `--file`로 넘긴다.
4. 업무 판단(맞다·틀리다, 비교 기준, 양식)은 스킬에 기준 문장으로 적는다. 판단 결과는 근거와 함께 보여 주고, 사용자가 넣으라고 하지 않은 판단은 문서를 바꾸기 전에 확인을 받는다 (3장 5번, `--dry-run` 뒤 `confirm_commands`).
5. 결과 처리는 4장, 승인은 5장을 따른다고만 적고 같은 규칙을 다시 쓰지 않는다.
