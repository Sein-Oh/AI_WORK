# mbom-diff 스킬 (MBOM 두 판의 변경 찾기)

명령 하나로 끝난다 (읽기·경로 계산·비교·요약을 도구가 차례로 함). 결과 처리는 전역 지침 4장, 승인은 5장을 따른다.
한 판에서 품목이 쓰인 곳을 찾는 일은 where-used, 지난 비교들을 모은 변경 이력은 bom-history다.

## 명령
PowerShell에서는 명령 앞에 전역 지침의 인코딩 줄을 붙인다. `<...>`만 바꾼다. 1번만 실행한다.

`python "C:\AIKIT\bom-kit\bom.py" diff --old "<옛 판.xlsx>" --new "<새 판.xlsx>"`

- 시트와 표는 도구가 찾는다. 사용자가 시트 이름을 말했을 때만 끝에 `--sheet "<시트>"`를 붙인다 (그 시트가 없으면 도구가 `[후보]`로 묻는다).
- 도구가 시트·표 범위·열 이름을 `[후보]`로 물으면 사용자에게 보여 주고, 고른 번호의 `confirm_commands` 명령을 1번 실행한다.
- 다른 명령(pandas-kit 등)을 섞지 않는다. 표를 직접 비교하지 않는다.

## 도구가 비교하는 기준 (사용자가 물으면 알린다)
1. 상위 품번 = 위쪽 행 중 가장 가까운, Level이 더 작은 행. 품목마다 최상위부터 품번을 `/`로 이은 경로로 두 판의 짝을 맞춘다
   (같은 상위 아래 같은 품번이 둘 이상이면 `#1`, `#2`).
2. 품번만으로도, 엑셀 행 번호로도 짝을 맞추지 않는다 (공용 부품, 행 밀림). 순서만 바뀐 것, 글자 숫자가 숫자로 바뀐 것, 표 위 제목 블록은 변경이 아니다.
3. 다른 상위 아래로 옮겨진 품목은 삭제와 추가로 알린다. 같은 자리(앞이나 뒤의 형제 품번이 같음)에서 품번이 바뀌면 대체 후보다 (품명은 보지 않음).

## 결과 알리기
- `preview`를 그대로 알린다 (첫 줄은 건수, 줄마다 `[대체 후보]`, `[추가]`, `[삭제]`, `[바뀜]`과 옛·새 엑셀 행, 끝 줄은 읽은 표). 줄을 직접 세거나 고쳐 쓰지 않는다.
- `warnings`가 있으면 그대로 알린다 (표 위의 내용, 숨긴 행, 글자로 저장된 숫자 등).
- 잘렸으면(`truncated: true`) 전체는 `output_file`(요약 .txt)에 있다고 알린다.
- `[대체 후보]`가 있으면 대체가 맞는지 사용자에게 묻는다.
- 원본 엑셀에 바뀐 칸을 칠해 달라고 하면 되묻지 말고 결과의 `confirm_commands`를 하나씩 1번 실행한다 (칠해 달라고 하지 않았으면 실행하지 않는다).
  그 대화의 앞 결과에 있던 `confirm_commands`도 그대로 쓴다 (칠할 칸 파일은 결과 폴더에 남아 있다).
