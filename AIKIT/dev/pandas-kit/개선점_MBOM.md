# pandas-kit 개선점 (MBOM_DR200.xlsx로 직접 써 보며)

반영 전 메모. 반영하면 CHANGELOG로 옮기고 여기서 지운다. 시험 파일: `python AIKIT/dev/pandas-kit/tools/make_mbom_samples.py`로 만드는 `AIKIT/dev/work/pandas/MBOM_DR200.xlsx`
(MBOM 시트 B6:R116, 17열 110행, 상위 품목 열 없이 Level로만 구조, 시트 MBOM·Routing·변경이력)와 `MBOM_DR200_v2.xlsx`(Qty 두 칸 바꾸고 110050 행 삭제).

## 사용자 결정
- 작업 폴더 이름 `<대상 파일 이름>_YYMMDDHHMM` (같은 분이면 `_2`): 0.2.0에서 반영.

## A. 결과가 틀리는데 알리지 않음: 0.1.2에서 고침 (CHANGELOG)

## B. 계층 BOM (상위 찾기, 누적 수량, 총소요량): 도구가 아니라 MBOM 스킬로 (사용자 결정 2026-11-13)
pandas-kit은 office-cli 같은 기반 도구. 0.2.0 작업 중 넣었던 `tree`·`rollup`은 빼고, 검증한 계산 방식만 스킬을 만들 때 참고:
- 상위 = 위쪽 행 중 가장 가까운, Level이 더 작은 행. 경로(`DR-200>100300>300210`), 같은 상위 아래 같은 품번은 `#2`로 구분해 경로가 행마다 다르게.
- 누적 수량 = 상위 수량들의 곱 (최상위 1개당). MBOM_DR200에서 000125 = 31개(10곳), RM-1001 = 0.56kg(11곳).
- 두 판 비교 = 두 판에 경로를 만든 뒤 `diff --on 경로`, 누적 수량·상위 행처럼 계산으로 나온 열은 비교에서 뺌.
  (`Part Number`나 `Level,Part Number,Op No`로는 키가 겹쳐 diff가 멈춤: v1 34행·21행. 0.2.1부터 멈출 때 겹치는 키와 엑셀 행을 보여 줌)
- 판단할 것: 스크랩·유효 기간·대체 그룹(수량 0)·팬텀 반영 여부.
- 스킬이 조합하려면 기반 도구에 필요한 것: 스킬 스크립트가 계산한 열을 엑셀 위치를 잃지 않고 pandas-kit 표로 되돌리는 방법
  -> 0.2.0: export한 csv에 계산 열을 더해 select로 읽고 `join --on "엑셀 행=엑셀 행번호"`. 이름 다른 키 `--on "A=B"`.

## C. 표 다루기 기능 부족: 0.2.0에서 고침 (표 찾기, group, sort, show --start, 이름 다른 키·엑셀 행 키 join; CHANGELOG)

## D. 잘 된 것
- `--range B6:R116`로 읽으면 열 종류(숫자·글자·날짜), 앞자리 0 품번(000125), 숨긴 행 warnings, 메모 블록 제외가 맞음.
- 조건: 빈 칸(`Eff To=` 108행), 날짜(`Eff From>2026-12-31` 1행), 포함(`Description~볼트` 10행, `~나사|와셔` 11행), 열 글자(`C=000125`), 여러 조건, `--columns "H,C"`.
- 다른 시트 `--sheet Routing` (A1:F15 14행), `export`, `show`의 `truncated`·`full_result_file`·`--start`.
- `group --by "Part Number" --sum Qty` (76묶음, 엑셀 행 목록), 단위 섞임 경고와 단위별로 나누는 명령, `sort` (빈 칸은 끝), `undo`.
- `chart`: 단위 섞임, 같은 x 합계, 막대 30개 경고. `join --on "Part Number=Item,Op No"`(4행).

## E. 기반 명령을 두 판으로 써 보며 찾은 '결과가 틀리는데 알리지 않음': 0.2.1에서 고침 (CHANGELOG)
1. `select --where "Part Number=125"`, `"Op No=10"`: 글자 열이라 0건인데 말이 없음 -> 숫자로 같은 값이 다르게 적힌 칸을 `warnings`.
2. `--where "Eff From>2026-13"`(없는 달)·`"2026-12"`: 날짜 열인데 글자 비교로 1행을 냄 -> 연-월-일만 받음.
3. `join --left v1 --right rt --on "Part Number=Item"`: 110행 중 104행이 짝이 없어 빠지는데 말이 없음 -> 빠진 행 수.
4. `join --on "Part Number"`(Routing에 없는 이름): 오른쪽 열 후보가 철자 순이라 맞는 `Item`이 둘째 -> 겹치는 값 많은 순.
5. `only --on "Part Number"`: 키가 34행 겹쳐, 지운 행의 품번이 다른 행에 있으면 결과에서 빠짐 (이번 v2는 110050이 한 곳뿐이라 맞게 나옴) -> `warnings`.
6. `diff`가 키 겹침으로 멈출 때 어느 키인지 모름, 안내에 BOM 용어 -> 겹치는 키·엑셀 행 예 3개, 용어는 뺌.
7. 표 위 내용 경고가 한 칸짜리 제목 줄(1행)을 세지 않음 -> 1~4행.
8. `export` xlsx의 날짜가 `2026-01-01 00:00:00`으로 보임 -> `yyyy-mm-dd`.

## F. 정할 것 (동작을 바꿀지 사용자가 정함, 바꾸지 않음)
1. `--file`·`--from` 없는 `select`: 지금은 만든 표가 있으면 지금 표, 없으면 열린 Excel 통합문서. 늘 열린 통합문서(또는 늘 지금 표)로 할지.
2. `line` 차트의 같은 x: 지금은 합계하지 않고 표 순서대로 모든 점을 이음 (MBOM `--x Level`은 110점이 1~4를 오가는 선). 막대처럼 합계할지, 경고만 할지.
3. `show --work`가 지금 작업 폴더를 바꿈 (보기만 하는 명령인데 다음 명령의 대상이 바뀜). 보기는 바꾸지 않게 할지.
4. 글자 열의 `=` 숫자 비교: 0.2.1은 글자 그대로 비교하고 경고만 (`125`는 `000125`와 다름). 숫자로 같으면 맞는 것으로 볼지.
5. `join`은 양쪽에 있는 행만 (inner). 왼쪽 행을 모두 남기는 방식(left)을 옵션으로 둘지 (0.2.1은 빠진 행 수만 알림).
6. `group --sum`이 `Scrap %`처럼 비율 열도 더함 (MBOM RAW 22행 합계 79). 비율 열을 알아보고 경고할지 (단위 열처럼).
7. `group`의 빈 값 묶음이 `null`로 나옴 (`Alt Group` 빈 칸 106행). `(빈 칸)`처럼 글로 보여 줄지.
