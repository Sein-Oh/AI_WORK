# 실기 테스트 (ml-kit 2.9.92, office-cli 1.6.7)

회사 PC(Windows 11, Office 16, 문서 보안)에서 1. 준비 -> 2. 자동 점검 -> 3. Gemma(선택) -> 4. 눈 확인 -> 5. 올릴 파일 순서로 합니다.
자동 점검은 명령 하나, 결과 파일 하나입니다. 사람이 판정하는 것은 4의 표 10줄뿐입니다.

## 1. 준비 (15분)
반입할 때마다 도구와 시험 폴더를 통째로 지우고 새로 붙여넣습니다. 지우기 전에 올릴 결과 파일(5장)이 남아 있지 않은지 확인합니다.

1. `C:\AIKIT\ml-kit`, `C:\AIKIT\office-cli`, `C:\AIKIT\pandas-kit`, `C:\AIKIT\bom-kit`, `C:\AIKIT\dev`, `C:\AIKIT\guide`, 기본 스킬 15개 폴더(`C:\AIKIT\.opencode\skills\ml-train` 등), `AGENTS.md`, `opencode.json`,
   `setup.py`·`setup.bat`·`web.bat`을 지우고 저장소 `AIKIT\` 아래 같은 것을 붙여넣습니다 (`.opencode\skills` 폴더를 통째로 지우지 않음: 사용자 스킬).
   `C:\AIKIT`의 나머지(`python\`, `opencode.exe`, 사용자 스킬 폴더, `data\`)는 그대로 둡니다.
   예전 구성(2026-11-13 이전, `C:\AIKIT\skills`)에서 옮기는 한 번: `C:\AIKIT\opencode.jsonc`는 그대로 두면 setup이 전역 설정 폴더로 옮깁니다.
   `C:\AIKIT\skills`의 사용자 스킬 폴더는 `C:\AIKIT\.opencode\skills`로 옮긴 뒤 `C:\AIKIT\skills` 폴더를 지웁니다 (예전 환경 변수는 setup이 지움).
   도구 폴더 안의 오류 로그(`data\logs`), 문서 캐시, office-cli `config.json`도 함께 지워집니다. `config.json`이 없어도 차트 전달은
   export -> redraw -> relay 순서로 자동 시도하므로 따로 할 일은 없습니다 (`transfer --probe`는 되는 방식을 먼저 쓰게 순서만 기억하는 선택 사항).
   모든 시험 폴더는 `C:\AIKIT\dev\work\` 아래에 생기므로 함께 지워집니다 (베타 점검, 실기 러너, Gemma, 눈 확인).
2. 설치: `C:\AIKIT\setup.bat`을 두 번 클릭합니다 (또는 PowerShell에서 `python C:\AIKIT\setup.py`). 끝에 `[STATUS] 결과`의 FAIL이 0인지 보고,
   새 터미널을 열고 OpenCode(TUI, Desktop, Web UI)를 모두 닫았다가 다시 시작합니다.
   OpenCode는 `C:\AIKIT`을 프로젝트로 연 대화(web.bat, `C:\AIKIT`에서 실행한 `opencode`)에서만 `AGENTS.md`(전역 지침)와 `.opencode\skills`(스킬 15개)를 읽습니다.
   setup은 `C:\AIKIT\opencode.json`의 셸·권한·폐쇄망 잠금을 전역 설정 `%USERPROFILE%\.config\opencode\opencode.json`에 합치고(원래 파일 보관),
   예전 설치가 남긴 사용자 환경 변수 `OPENCODE_CONFIG_DIR=C:\AIKIT`를 지웁니다.
   시스템 PATH에 `C:\AIKIT\python`, `C:\AIKIT\python\Scripts`가 없으면 추가하고 (원래 값도 같은 보관 폴더에), 라이브러리 import·도구 `-h`·`opencode.exe`·rg와
   `opencode debug paths`의 config가 전역 설정 폴더인지 확인합니다.
   `--check`는 아무것도 바꾸지 않고 다른 것만 보여 줍니다. 자동 점검의 환경 진단도 같은 것(PATH, 예전 환경 변수)을 확인해, 다르면 FAIL로 알려 줍니다.
   Gemma 테스트를 하면 `opencode.exe`(CLI)가 `C:\AIKIT`나 PATH에 있고, `%USERPROFILE%\.config\opencode\opencode.jsonc`의 `model`이 Gemma여야 합니다.

## 2. 자동 점검 (40~70분, 질문 없음, 자리 비워도 됨)
열린 Office 문서를 모두 저장하고 닫은 뒤 PowerShell에서:

```powershell
cd C:\AIKIT\dev
python run_all_tests.py --label 회사PC
```

- 순서: 환경 진단(라이브러리, 문서 보안 영향) -> ml-kit 베타 점검(`run_beta_check.py`, F7 엑셀 재계산 포함) -> 사용법 단순성 점검(`run_simplify_check.py`, 틀린 명령에 도구가 준 `[추천]`·`[후보]` 명령이 그대로 되는지) -> office-cli 실기 러너(실제 Office) -> 도구 오류 로그(`errors.txt`) 붙이기.
- 결과: `C:\AIKIT\dev\result_회사PC_<시각>.md` 하나. 맨 위 요약 표(단계별 PASS/FAIL/SKIP)와 실패, ENV-SKIP, UNVERIFIED 목록을 보면 됩니다. Ctrl+C로 끊어도 그때까지 남습니다.
- 회사 PC에서는 베타 점검 F7(엑셀 재계산)까지 PASS여야 합니다. 요약 표 베타 점검 줄의 "비고"에 4장에서 열 성능예측표 경로가 있습니다.
- 선택 옵션: `--outlook`(office 러너에 Outlook 포함), `--ask`(office 러너의 눈 확인 질문에 답하며 진행), `--only diag,beta`(일부 단계만. `ml`을 넣으면 ml-kit 실기 러너도).
- 한 단계만 다시: `python run_all_tests.py --label 회사PC --only beta` (단계 이름: diag, beta, simplify, ml, office, gemma).

## 3. Gemma 종합 테스트 (선택, 20~60분)
2장 명령에 `--gemma`를 붙이면 자동 점검 끝에 이어서 합니다. 따로 하려면 `--only gemma`.
**관리자 권한이 아닌 일반 PowerShell**에서 실행합니다 (창 제목에 "관리자"가 없어야 함).
UAC가 꺼진 PC(`reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v EnableLUA`가 `0x0`, 회사 PC)는 모든 창이
관리자로 뜨고 Office도 같으므로 평소 PowerShell에서 그대로 합니다. `runas /trustlevel`로 권한을 낮춘 창은 쓰지 않습니다
(제한 토큰이라 사용자가 연 Office 문서에 닿지 못해 "열린 문서 없음"이 납니다).

```powershell
cd C:\AIKIT\dev
python run_all_tests.py --label 회사PC --gemma
```

- `agent_scenarios.py`의 요청 22개(S -> A -> M -> P -> R -> O -> Y -> X, 준비 S와 수동 전용 O3 제외)를 `opencode run --format json`으로 한 세션에 차례로 보내고 채점합니다.
- O는 office-cli 묶음입니다 (S1이 만든 샘플을 닫힌 파일 경로로 씀, Excel·Word 필요). 열린 Office 문서는 닫아 둡니다.
  O1 규격 대조(`excel.py read` + `reader.py search`로 조합, 메모는 `--dry-run` 미리보기까지만), O2 여러 칸 쓰기(`excel.py write --cells` 한 번),
  O4 워드 문단 덧붙이기(`word.py write`), O5 양식 채우기(`word.py fill --file`). 회사 PC 오류 로그에서 나온 지어낸 옵션
  (`excel.py write --text/--cell`, `office.py write`, `transfer --source/--text`, `undo --target`, `excel.py list`)은 모든 요청에서 실패입니다.
- O3(메일 첨부 받아 읽기)은 Outlook 메일이 필요해 자동으로 보내지 않고 "건너뜀(수동 전용)"으로 남습니다. 해 보려면
  `C:\AIKIT\dev\work\gemma\시험성적서.docx`를 첨부하고 제목에 "시험성적서"가 들어간 메일을 자신에게 보낸 뒤,
  OpenCode 새 대화에 아래를 붙여넣고, 첨부를 저장한 뒤 읽어 판정 결과를 알리는지 봅니다 (눈 확인 표 아래 메모에 O/X):
  ```text
  [O3] Outlook 받은 편지함에서 제목에 시험성적서가 들어간 메일을 찾아 첨부파일을 C:\AIKIT\dev\work\gemma\메일첨부 폴더에 저장하고, 그 첨부 내용을 읽어서 판정 결과를 알려줘.
  ```
- 시험 폴더는 `C:\AIKIT\dev\work\gemma`입니다. 이미 있으면 지우지 않고 `gemma_old_<시각>`으로 이름을 바꿉니다.
- 요청별 기록은 `C:\AIKIT\dev\work\gemma_runs_<시각>\`(`<ID>.jsonl`, 채점 보고서)에 남고, 채점 결과는 결과 파일의 Gemma 단계에 들어갑니다.
  반출용으로 그 폴더를 결과 파일 옆 `result_회사PC_<시각>_gemma기록.md` 하나로 묶습니다 (요청마다 모델의 글과 도구 호출·결과를 순서대로, 사용자 이름 가림).
- 첫 요청에 응답이 없으면(모델 설정, 접속 문제) 나머지는 보내지 않고 FAIL로 끝납니다. 요청 하나의 시간 상한은 `--gemma-timeout`(기본 900초).
- 일부만: `--gemma-only A1,P1`. 시험 자료 준비(S0·S1)는 러너가 직접 실행하고 모델에 보내지 않습니다 (고르지 않아도 늘 먼저). 모델 지정: `--gemma-model <모델>,<예비 모델>`
  (사용량 제한이면 예비 모델로 같은 요청을 다시 보냄, 요청별 모델은 채점 보고서 머리에). 회사 PC는 보통 둘 다 필요 없음 (opencode 설정의 사내 Gemma).
- **합격 기준은 Gemma 4 26B 결과만**입니다 (2026-11-08). 집 PC는 `--gemma-model "openrouter/google/gemma-4-26b-a4b-it,upstage/solar-mini4"`처럼
  Gemma를 먼저, solar-mini4는 Gemma 사용량이 다 됐을 때 이어 받는 예비로만 씁니다. solar-mini4에서만 난 실패는 기록만 남깁니다
  (도구 `[추천]`이 나아지거나 지침·스킬이 짧아지는 수정일 때만 고침). 요청별로 답한 모델은 채점 보고서 머리의 "요청별 모델"로 봅니다.
- "건너뜀"에 X2가 나오면 자유 문장 답이라 사람이 결과 파일의 "최종 답변"을 읽고 정합니다 (옵션이 없다고 했는지, '제외' 열을 안내했는지).
- 다시 채점만: `python C:\AIKIT\dev\grade_opencode.py --runs C:\AIKIT\dev\work\gemma_runs_<시각> --label 회사PC`.
- 요청 문장과 채점 기준(필요한 명령, 금지 행동)은 `AIKIT/dev/agent_scenarios.py` 한 곳에 있습니다.
- (선택) 끝에 opencode에서 "공정_다중출력.xlsx로 학습해 줘. 입력은 반응온두, 촉매비율, 출력은 생산효율"(오타)을 보내면, Gemma가 다시 실행하지 않고 `[후보]`(반응온도)를 보여 주며 묻는지 봅니다 (채점기 밖, 눈 확인 표 아래 메모에 O/X).

## 부록: 집 PC(Office 16)로 먼저 할 때
인터넷이 되는 집 PC(Windows 11, WinPython 3.13.13, Office Professional Plus 2019)에서는 이 문서 1장대로 준비한 뒤
`python run_all_tests.py --label 집PC`를 실행합니다. F7은 Excel로 성능예측표 수식(INDEX/MATCH, IFERROR)이 계산되는지 봅니다.
눈 확인은 1, 3~8번만 (2번 문서 보안과 Outlook, Gemma는 회사 PC 몫).
