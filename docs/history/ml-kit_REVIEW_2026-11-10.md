### 1. 틀린 결과·쓸 수 없는 결과를 VERIFIED로 내는 결함, 조용한 데이터 손실 (가장 급함)

#### A1. 머리글 칸에 줄바꿈(Alt+Enter)이 있으면 학습은 VERIFIED인데 그 모델로 예측이 안 됨 (재현, 높음)
- 증상: 타겟 머리글이 `수율\n(%)`(엑셀에서 Alt+Enter로 두 줄, 사내 표에 흔함)이면 열 이름에 줄바꿈이 그대로 남는다.
  학습은 `VERIFIED: v1 학습을 마쳤습니다`인데 모델 파일 이름이 `model_수율<줄바꿈>(%).joblib`이 되고,
  `ml_predict.py --model <v1>`은 `조건에 일치하는 대상 모델을 찾을 수 없습니다 (filter=None)`로 실패한다.
  preview와 `next_commands`(`--input '반응온도<줄바꿈>(°C)=<값>,...'`)에도 줄바꿈이 들어가 명령이 두 줄이 된다 (타겟이 아니라 입력 머리글만 줄바꿈이어도).
- 위치: `_ml_runtime.py:2918-2925`(`_cell_text`: strip만 하고 안쪽 공백·줄바꿈은 그대로), `1180-1185`(`sanitize_filename`: 줄바꿈·제어문자를 바꾸지 않음),
  `4279`(`re.match(r"^model_(.+)\.joblib$")`: `.`이 줄바꿈과 안 맞아 그 모델을 건너뜀).
- 재현: 머리글 `["반응온도\n(°C)", " 압력 (bar) ", "라인\n구분", "수율\n(%)"]` + 기본 표 30행.
  `ml_train.py --file nl.xlsx --targets 수율` -> ok/VERIFIED, `ls v1`에 줄바꿈이 든 파일 이름.
  `ml_predict.py --model nl_ml_data/v1 --input "반응온도=180,압력=3,라인구분=A"` -> error (대상 모델 없음). `--file nl.xlsx` 예측도 같은 오류.
- Windows(추정 90%): 파일 이름에 줄바꿈을 쓸 수 없어 버전 저장 단계에서 OSError -> `ERROR:`(internal)로 학습 자체가 실패할 것. 실기 확인 필요.
- 고칠 방향: `_cell_text`에서 머리글·단위 칸의 연속 공백/줄바꿈을 빈칸 하나로 접는다(학습·예측이 같은 함수라 함께 바뀜). `sanitize_filename`은 제어문자도 `_`로.
  `verify_version_dir` 뒤에 "방금 저장한 폴더를 `resolve_target_models`로 다시 읽어 타겟 수가 맞는지" 확인을 넣으면 같은 부류를 UNVERIFIED로 잡을 수 있다.

#### A2. 합계 행이 있으면 숫자 입력이 전부 "타겟 누수"로 빠지고, 쓸모없는 모델이 VERIFIED (재현, 높음)
- 증상: 표 맨 아래에 합계 행이 있으면(사내 표에 흔함) 합계 한 점 때문에 모든 숫자 열과 타겟의 상관계수가 0.999 이상이 된다.
  `--features` 없이 학습하면 숫자 입력이 전부 `타겟 누수`로 제외된다.

  - 남는 열이 없으면: `STOP_RETRY: ... 쓸 수 있는 열이 없습니다 ('온도': 타겟 누수; '압력': 타겟 누수)` (원인이 합계 행이라는 말이 없음).
  - 도구가 경고한 대로 `제외` 열에 `합계`, `평균`을 적고 다시 실행해도 똑같이 누수로 빠진다 (R2 -0.07, VERIFIED).
- 위치: `ml_train.py:1989-2037`(`diagnose_inputs`: `tvals`와 각 열을 `df` 전체 행으로 계산, `1998-2001`), `1929-1947`(`_leak_reason`),

  `ml_train.py --file b_total_label.xlsx --targets 수율` -> ok, preview `입력 자동 선택 1개, 뺀 열 2개: 온도(타겟 누수), 압력(타겟 누수) | 평균 검증 R2=-0.0699`.
  E열에 `제외` 머리글, 합계·평균 행에 `합계`/`평균`을 적은 파일도 같은 결과. 합계 글자가 없는(숫자만 있는) 합계 행 + 숫자 열만 있는 표는 STOP_RETRY.
- 고칠 방향: 입력 진단(누수·ID·상수·빈 칸)은 "학습에 쓰는 행"으로만 한다: `제외` 표시 행, `summary_rows`, 타겟 기준 자동 이상치 후보를 뺀 뒤 계산.
  합계 행으로 판정한 행은 기본으로 학습에서 빼는 것도 검토(지금은 경고만 하고 합계는 이상치로 우연히 빠지고 평균 행은 학습에 들어감).

#### A4. 입력 자동 선택이 진짜 예측 변수를 빼고 나쁜 모델을 VERIFIED로 냄 (재현, 높음)
세 가지 경로. 모두 preview의 "뺀 열"에는 나오지만 결과는 `VERIFIED`이고 스킬은 "입력 열은 묻지 않는다"라서 경량 LLM은 그대로 전한다.

  `뺀 열 1개: 경과일(일)(ID·일련번호) | 평균 검증 R2=-0.0875`. 경과일·사용 횟수·회차·시간(분)처럼 타겟을 좌우하는 열이 빠진다.
  위치 `ml_train.py:1960-1979`(`counting` 규칙: 타겟과의 관계를 보지 않음).
- (b) 상관 0.98 이상이면 무조건 누수(`AUTO_LEAK_CORR`, `1919`, `1939-1944`): `점도 = 100 - 온도/3 + 잡음(1)`(R2 0.96짜리 정상 관계)에서 `온도`가 누수로 빠짐.
  검량선·단일 지배 인자 같은 깨끗한 실험 데이터에서 일어난다.
- (c) 타겟이 여럿이면 한 타겟에만 "누수"여도 모든 타겟에서 빠짐: `--targets 수율,강도,점도`에서 온도가 점도 때문에 빠져
  수율 R2 0.49(온도를 넣으면 0.9대), 점도 R2 -0.008. 위치 `_leak_reason`의 `for t in targets` + `auto_inputs`가 열 단위로만 제외.
- 재현 (b)(c): 200행, `온도, 압력, 라인, 수율(=30+0.2T+3P+N(0,1)), 강도(=T*P/10+N(0,2)), 점도(=100-T/3+N(0,1))`.

  누수는 이름이 같거나(단위만 다름) 상관이 사실상 1(예: 0.9999, 다른 단위·배율 사본)일 때만 자동 제외, 0.98~0.9999는 입력으로 두고 warnings(의심 입력, 지금 `--features`를 줬을 때와 같은 처리).

#### A8. CSV에 빈 줄이 있으면 행 번호가 어긋나 다른 행이 제외됨 (재현, 중간)

  `ml_dataset.py exclude --file blank.csv --rows 15`는 `VERIFIED`로 다른 행(파일 17번째 줄)에 `제외`를 적고 9999 행은 그대로 남는다.

#### A9. 두 줄 병합 머리글에서 윗줄을 머리글로 써서 `col_1` 같은 이름으로 학습 (재현, 중간)

### 2. 계약 위반·내부 오류·실행해도 안 되는 [추천]

#### B1. `[추천] ... --header-row N --unit-row M`이 단위를 두 번 붙여 추천 명령이 실패 (재현, 중간)
- 증상: 머리글에 이미 단위가 있는 열(`압력(bar)`, `생산 효율(%)`)과 그 아래 단위 행(`bar`, `%`)이 함께 있는 표에서, 제목 행 때문에 타겟을 못 찾으면
  `[추천] python ... --targets '생산 효율' --header-row 3 --unit-row 4`를 준다. 그대로 실행하면 열 이름이 `압력(bar)(bar)`, `생산 효율(%)(%)`이 되어
  `타겟 ... 찾을 수 없습니다 ... [후보] 1) '생산 효율(%)(%)'`로 다시 멈춘다 (추천을 1번 실행해도 끝나지 않고, 고르면 `(%)(%)` 이름으로 학습됨).
- 위치: `_ml_runtime.py:2927-2929`(`_with_unit`: 머리글에 같은 단위가 이미 있는지 보지 않음), `2416`, `1236-1241`(`strip_unit`은 꼬리 하나만 뗌), `3251-3266`.
- 재현: 1행 `공정 조건 표, 작성: 홍길동`, 2행 빈 행, 3행 `반응 온도, 압력(bar), 촉매 종류, 생산 효율(%), 강도`, 4행 `°C, bar, (빈칸), %, MPa`, 40행.
  `ml_train.py --file "공정 데이터 (1).xlsx" --targets "생산 효율"` -> [추천] 실행 -> 다시 STOP_RETRY.
- 고칠 방향: `_with_unit`에서 머리글이 이미 `(<같은 단위>)`로 끝나면 붙이지 않는다(다른 단위로 끝나면 경고). 회귀 테스트는 "도구가 낸 [추천]을 그대로 실행하면 ok"로.

#### B2. `inf` / `Infinity` / `1e400` 글자 칸이 있으면 `ERROR:`(internal) (재현, 중간)
- 증상: 숫자 열이나 타겟의 칸 하나가 글자 `inf`(계측기 내보내기의 `Inf`, `INF` 포함)면
  `ERROR ... ValueError: Input X contains infinity or a value too large for dtype('float64')`(타겟이면 `Input contains infinity`). 내부 오류라 재시도 금지로 끝나고 어느 칸인지 모른다.
- 위치: `_ml_runtime.py:2029`(`pd.to_numeric`이 `inf`, `1e400`을 무한대로 읽음, 뒤에 유한값 검사 없음). `--eval` 결과는 `3632`에서 무한대를 빈 값으로 바꾸는데 원본 열은 안 바꿈.
- 재현: 기본 표 12행의 A5 칸(또는 C5 칸)을 글자 `inf`로. `ml_train.py --file inf_x.xlsx --targets 수율`.
- 고칠 방향: `coerce_numeric` 끝에서 무한대를 NaN으로 바꾸고(학습·예측 공통), 학습은 "숫자로 읽지 못한 칸" 경고에 포함.

#### B3. `제외` 열이 Y/N, O/X, `-`이면 전 행이 빠지고 오류 문구가 원인을 말하지 않음 (재현, 중간)
- 증상: `제외` 열에 `N`(대부분)/`Y`, 또는 `-`/`이상`, 또는 `X`/`O`를 적은 파일 -> 빈 칸·`0`·`FALSE`·`포함`이 아닌 글자는 모두 "제외"라서 30행 전부 빠지고
  `타겟 '수율'의 유효 학습 샘플 수가 너무 적습니다 (0개). 최소 10개 이상 필요합니다.`만 나온다. `제외` 열 때문이라는 말이 없어 LLM도 사용자도 원인을 알 수 없다.
  결측 표시 `-`도 제외 표시로 읽힌다(다른 열에서는 `-`가 빈 값).
- 위치: `_ml_runtime.py:2579-2590`(`exclude_mark`), `ml_train.py:1806-1810`, `931-932`(오류 문구).
- 재현: 기본 표 30행 + `제외` 열. `ml_train.py --file yn.xlsx --targets 수율`.
- 고칠 방향: (1) `-`, `N`, `No`, `X`(아니오 뜻), `아니오`, `N/A`는 "표시 없음"으로 읽거나, 뜻이 갈리는 값(`N`/`Y`, `O`/`X`)이 열을 채우고 있으면
  STOP_RETRY로 "제외 열의 값 종류: N 28칸, Y 2칸. 뺄 행에만 이유를 적고 나머지는 비우십시오"를 알린다.
  (2) 직접 표시로 학습 행이 10개 미만이 되면 오류 문구에 "제외 열 표시 N행" 내역을 넣는다.

#### B4. 연속 수치 타겟에 `--task classification`을 주면 메시지가 무제한으로 길고 회귀 안내에 닿지 못함 (재현, 낮음)
- 증상: 200행 수치 타겟 -> `샘플이 1개뿐인 클래스 ['63.14', '63.52', ...]`에 클래스 목록과 `[클래스별 건수]` 딕셔너리 전체가 들어가 stdout JSON이 4.6KB(300행이면 더 큼).
  `클래스가 N개로 너무 많습니다. 연속형 수치라면 --task regression` 검사는 그 뒤에 있어 실행되지 않는다. 날짜 타겟도 같음.
- 위치: `ml_train.py:1146-1151`(rare 검사가 먼저), `1152-1155`(50개 초과 검사), 목록에 `name_list` 상한 미적용.
- 고칠 방향: 클래스 수 검사를 먼저 하고(대부분의 클래스가 1건이면 회귀 타겟으로 보고 `[추천] <--task classification을 뺀 전체 명령>`), 목록은 `name_list`로 자른다.

#### B5. `--eval` 오류와 조용한 수식 변경 (재현, 낮음~중간)
- `제곱 = 온도^2` -> `보안 위반: 허용되지 않은 문법 노드 감지: BitXor`. 경량 LLM이 거듭제곱을 `^`로 쓰는 일은 흔한데 뜻이 하나뿐인 실수에 `[추천]`이 없고 문구가 겁을 준다
  (`_ml_runtime.py:3477-3478`). `x = 온도 if 압력 else 0`도 같은 문구. -> `^`는 `**`로 바꾼 전체 명령을 `[추천]`, 나머지는 "쓸 수 있는 것: + - * / ** 와 함수 목록".
- `','는 max(a, b) 같은 함수 안에서만`이라고 안내하지만(`ml_train.py:136-137`) `max`는 허용 함수가 아니다(`큰값 = max(온도, 압력)` -> 허용되지 않은 함수). 예시를 `clip(a, 0, 1)`로.
- `로그 = log(온도 - 180)`처럼 음수가 섞이면 `log(|x|)`로 계산하고(`sqrt`, `log10`, `log1p`도 절댓값, `_ml_runtime.py:3446-3450`) 경고 없이 `VERIFIED`.
  수식의 뜻이 바뀌는 일이라 warnings에 "음수 N행은 절댓값으로 계산"을 넣거나 그 행을 빈 값으로.
- `비 = 온도 / (압력 - 압력)`(전부 0 나눗셈) -> `컬럼 ['비']에 숫자로 변환 가능한 값이 하나도 없습니다. 헤더/데이터 시작 행을 확인하십시오`(원인과 다른 안내, `ml_train.py:2134-2138`).

#### B6. preview에 `검증 R2(제외 행 포함)=-inf` (재현, 낮음)
- 증상: 입력 칸 하나가 1e308 같은 극단값이면 그 행이 자동 제외되고, 제외 행을 최종 모델로 채점할 때 예측이 넘쳐 preview에 `-inf`가 그대로 나온다 (JSON 값은 null).
- 위치: `ml_train.py:1864-1876`(`score_with_excluded`), `3024`(preview 조립).
- 고칠 방향: 유한값이 아니면 preview에서 `계산 불가(제외 행의 예측이 범위를 넘음)`로 쓰고 warnings에 한 줄.

#### B7. 시간 제한 시계가 `run_cli` 시작부터라 프로세스 시작~import 시간이 빠짐 (코드, 추정 50%, 낮음~중간)
- 내용: `RUN_START`는 `run_cli`에서 다시 잡는다(`_ml_runtime.py:915`). 감시 타이머는 그때부터 100 + 15 = 115초 뒤에 JSON을 낸다(`608-617`).
  에이전트의 120초는 `python` 프로세스 시작부터이므로 pandas·scikit-learn import와 인자 해석에 5초 넘게 걸리는 PC(부팅 직후, 백신 검사)에서는
  한 단계가 길어진 실행이 JSON 한 줄 없이 끊길 수 있다. Linux에서 import는 1.2초였고 회사 PC 값은 확인하지 못했다.
- 고칠 방향: 진입점 맨 위(무거운 import 전)에서 시각을 잡아 `RUN_START`로 넘기거나, 감시 타이머를 "프로세스 시작 시각" 기준으로 (`time.time() - psutil 없이도` `os.times()`/모듈 최상단 시각으로 가능).
  실기 러너에 "import 포함 시작 시간" 측정 항목을 넣어 여유(5초)가 충분한지 본다.

### 3. 경량 모델 사용성·설계

#### C1. 성능 개선 루프가 같은 입력을 거듭 곱한 교차항을 쌓고, 잡음을 "최고 성능"으로 보고 (재현, 중간)
- 증상: 관계가 약한 데이터(60행, 참 R2가 낮음)에서 `next_commands[0]`을 따라가면 v2~v10까지
  `반응온도x압력` -> `반응온도x반응온도x압력` -> ... -> `반응온도x반응온도x반응온도x반응온도x압력`(온도^4*압력)을 계속 추가한다.
  검증 R2는 0.137 -> 0.200으로 조금씩 오르며 대부분 `is_best: true`. 같은 60행으로 10번 고른 것이라 교차검증 점수 자체가 과적합이고, `--eval` 문자열은 회차마다 길어진다.
- 위치: `ml_train.py:1716-1726`(상위 2개 숫자 입력의 곱, 파생변수와 그 재료의 곱을 막지 않음), `IMPROVE_ROUNDS`(`3110`, "최고가 아닌" 회차만 셈).
- 재현: 머리글 `반응온도(°C), 압력 (bar), 유속(m/s), 첨가제 비율(%), 라인, 수율(%)`, 60행, `수율 = 30 + 0.1T + P + N(0,3)`. 첫 명령 뒤 `next_commands[0]`을 10번.
- 고칠 방향: 교차항 후보는 원본 입력끼리만(파생변수는 재료에서 제외), 같은 쌍은 1번. 개선 폭이 잡음 수준(예: 0.01 미만, 또는 fold 간 표준편차 이내)이면
  "나아지지 않음"으로 세어 `improve_stopped`로 일찍 끝낸다. 회차 수에 절대 상한도 둔다.

#### C2. 0/1·TRUE/FALSE 타겟을 회귀로 학습해도 안내가 없고, 글자 타겟 회귀 오류에 `[추천]`이 없음 (재현, 낮음~중간)
- `불량여부`(0/1) 타겟을 `--task` 없이 학습 -> 회귀 `VERIFIED`, R2 0.88, 분류 얘기 없음. TRUE/FALSE 칸(`가동`)도 0/1 회귀로 학습됨. 스킬은 "모르면 묻는다"지만 LLM은 숫자면 회귀로 간다.
  -> 회귀 타겟의 값 종류가 2개(또는 정수 5종 이하)면 warnings에 "등급·여부로 보임, 분류는 `--task classification`"과 그 전체 명령을 `next_commands`에.
- 글자 타겟(`양품`/`불량`)을 회귀로 주면 `... 타겟이 범주(라벨)라면 --task classification을 지정하십시오`라고만 한다. 타겟 칸이 전부 글자면 뜻이 하나뿐이니
  `[추천] <--task classification을 붙인 전체 명령>`을 줄 수 있다 (`ml_train.py:335-340`).
- `--task clf` 같은 오타도 argparse 문구만 나오고 `[추천]`이 없다.

- 고칠 방향: 고정 입력 값 검사를 한 곳으로: 숫자는 유한한 수(`nan`, `inf` 거절), 날짜는 `parse_datetime`으로 읽히는지 확인하고, 읽지 못하면
  `STOP_RETRY`(사용자에게 날짜 확인). 학습 기간 밖 날짜는 한 건 예측과 같은 경고. 한 건 예측의 날짜도 숫자처럼 멈춤.
- 테스트: 위 경우가 VERIFIED로 나오지 않는 것, 기간 밖 날짜 경고.

#### A4. --input에 파생변수 이름의 값을 주면 받아 놓고 쓰지 않음 (재현, 중간)
- 위치: `ml_predict.py:1201` (`known_names`에 `derived_names` 포함 -> `check_inline_unknown` 통과), `1230` (`apply_inference_evals`가 그 열을 다시 계산해 덮어씀)
- 재현 (pe 모델): `--input "온도=180,압력=3,라인=A,편차=5"` -> `VERIFIED 수율(%) 95.9442`, `편차=5`가 없을 때와 같은 값. 경고 없음.
  학습 결과의 중요 입력에 `편차 0.77`이 맨 앞에 나오므로 경량 모델이 `편차` 값을 넣어 보는 일이 생깁니다.
- 고칠 방향: 파생변수 이름은 "모델이 원본 입력에서 계산하는 값이라 줄 수 없음"으로 `STOP_RETRY`(그 이름을 뺀 전체 명령을 `[추천]`: 값이 쓰이지 않으므로
  빼도 결과가 같음) 또는 받고 무시하되 `warnings`에 적는다 (AGENTS.md 사용법 단순성 4번).

#### A5. 실측 비교값: 날짜 입력을 무시해 좋은 모델에 "실측과 많이 다름" 경고, 외삽한 추세선 값을 표시 없이 "실측 비교값"으로 preview에 넣음 (재현, 중간)
- 위치: `ml_predict.py:200` (비교 기준 `keys`에서 날짜·파생 입력을 뺌), `1360-1376` (경고), `1522-1524` (preview 글)
- 재현 1 (dm 모델, 검증 R2 0.986): 학습 범위 안의 100행 파일을 `--file`로 예측 -> `map_check_warnings: 실측 비교값이 90% 예측 범위 밖인 건 87건
  (모델 예측과 실측 데이터가 많이 다름 ...)`. 비교값이 날짜를 무시하고 온도만으로 이웃 두 행을 보간한 값이기 때문입니다.
  한 건 예측도 `실측 비교값 91.795 (차이 -2.768) | 실측 비교 경고 1건`. 사용자는 모델을 믿지 못하게 됩니다.
  preview의 "실측 비교 경고 1건"은 행 수(87)가 아니라 타겟 수입니다.
- 재현 2 (para 모델): `--input "온도=250,압력=30,라인=B"` -> preview `수율(%) 68.4194 (90% 범위 66.2504 ~ 70.2393, 실측 비교값 129.008 (차이 -60.59))`.
  129.008은 실측이 아니라 "전체 추세선 외삽" 값인데(JSON의 `map_check[0].extrapolated: true`) preview에는 표시가 없습니다. 수율 129%가 "실측"으로 전달됩니다.
- 고칠 방향: 모델에 날짜 입력(또는 비교 기준에 못 넣는 입력)이 있으면 비교값을 내지 않거나 경고 대상(`warnable`)에서 뺀다.
  preview에는 외삽인 비교값을 넣지 않거나 `[외삽]`을 붙인다 (결과 파일의 `map_방식_*` 열은 이미 붙임). 경고 건수는 행 수로.

#### A6. --maximize/--minimize: --where에 --vary에 없는 입력을 쓰면 그 입력을 중앙값으로 고정해 놓고 "만족하는 조합 없음" (재현, 중간)
- 위치: `ml_predict.py:2300-2314`, `2410-2414`
- 재현 (para 모델): `--maximize 수율 --vary "온도" --where "압력 >= 4" --input "라인=A"` -> `VERIFIED: 0건 (학습 범위 안에서 조건을 만족하는 조합 없음)`,
  warnings "주지 않은 입력은 학습 데이터 중앙값으로 고정했습니다: 압력(bar)=2.8". 압력을 2.8로 고정했으니 조건이 맞을 수 없는데
  "조합 없음"으로 전달됩니다 (학습 범위는 1~5라 4 이상인 조합이 있음). 지시문은 "조건을 바꿔 다시 실행하지 마세요".
- 고칠 방향: `--where`가 가리키는 입력이 `--vary`에도 `--input`에도 없으면 도구가 그 입력을 `--vary`에 넣어 찾거나(판단 대행),
  `STOP_RETRY` + `[추천] <--vary에 그 입력을 더한 전체 명령>`.

#### A7. ml_map --find: 범위 밖 답에 한도가 없어 먼 외삽값이 VERIFIED 답으로 나감 (재현, 중간~낮음)
- 위치: `ml_map.py:589-602`
- 재현: `--file 맵.xlsx --find "B=5000" --vary A` -> `VERIFIED`, `A: 305.128 [외삽]` (표는 A 0~100, B=A^2/10이라 실제는 223.6. 데이터 폭의 2배 밖).
  `--file k1.xlsx --find "값=20" --vary 온도` (값은 최대 12인 산 모양) -> `온도: -137.579 [외삽]` (전체 추세선, 데이터 폭의 1.6배 밖, 음수 온도).
  `[외삽]`과 경고는 붙지만 지시문은 "VERIFIED: 찾은 답을 보간식에 다시 넣어 목표값이 나오는지 확인했습니다"이고 `count: 1`입니다.
- 고칠 방향: 범위 밖 답은 데이터 폭의 일정 비율(예: 20~30%)까지만 답으로 주고, 그보다 멀면 `count 0` + reachable(도달 가능한 범위)로 답한다.
  한 건 사잇값(`Table.at`)의 외삽도 같은 한도를 쓸지 함께 정한다.

### 2. 계약 위반 / 내부 오류 / 실행할 수 없는 안내

#### B1. JSON --input에 null이나 빠진 키가 있으면 내부 오류 (재현, 높음)
- 위치: `ml_predict.py:1214` (`df_input[c].astype(str)`가 pandas 3에서 NaN을 글자로 바꾸지 않아 `re.fullmatch`가 TypeError)
- 재현 (para 모델): `--input '[{"온도":180,"압력":3,"라인":"A"},{"온도":190,"라인":"A"}]'` 또는 `{"압력": null}`이 든 배열/.json 파일
  -> `error_type: internal`, `TypeError: expected string or bytes-like object, got 'float'`, `ERROR:`.
  스킬이 여러 건은 JSON 배열 파일로 주라고 안내하므로(ml-predict SKILL.md) 건마다 키가 다른 배열은 흔합니다.
- 고칠 방향: `v`를 `"" if pd.isna(v) else str(v)`로. 그 뒤에는 빈 숫자 입력 처리(중앙값 채우기 확인 `_offer_median_fill`은 한 건만 봄)가
  여러 건에서 어떻게 되는지도 함께 확인 (여러 건에서 빈 값이 조용히 채워지지 않게).
- 테스트: 위 입력이 내부 오류가 아닌 것.

#### B2. [후보] 묶음이 둘 이상인 message에 confirm_commands는 마지막 묶음 것만, 지시문은 없는 next_commands[0]을 가리킴 (재현, 중간~높음)
- 위치: `_ml_runtime.py:135-140` (`InputError`가 `_ASKED`에서 한 묶음만 고르고 `needs_user_decision`으로 바꿈), `701-708` (그 지시문),
  `ml_predict.py:342-381` (`_typo_hints`가 빠진 입력마다 `ask()`)
- 재현 (공정 모델): `--input "압축압=3,반응온두=180,반온도=1,촉매비율=1,수분함량=20,유량=10,분진=0.5"`
  -> message에 `'반응온도' ... [후보] 1) 반온도 2) 반응온두` 와 `'압축압력' ... [후보] 1) 압축압` 두 묶음, `confirm_commands`는 `압축압 -> 압축압력` 1개뿐.
  사용자가 첫 묶음의 "2번"을 고르면 실행할 명령이 없고, "1번"을 고르면 다른 묶음의 명령이 실행됩니다.
  `--input "온도=180,압력=3,..."`(둘 다 후보 1개)도 confirm_commands는 1개.
  또 이 경우(와 `--find`의 글자 입력 [후보], `_offer_find`의 [후보]) `agent_directive`가 "next_commands[0].command를 글자 그대로 1번 실행"이라고 하는데
  JSON에는 `next_commands`가 없고 `confirm_commands`만 있습니다.
- 고칠 방향: 한 message에는 [후보] 묶음을 하나만 (첫 번째 빠진 입력만 묻고 나머지는 다음 실행에서), 또는 묶음 전체에 이어지는 번호를 매겨
  confirm_commands를 합친다. `needs_user_decision` 지시문은 실제로 있는 키(confirm_commands / next_commands)에 맞춰 문구를 나눈다.
- 테스트: 묶음 2개인 message의 번호 수 == confirm_commands 수, 지시문이 가리키는 키가 JSON에 있는 것.

#### B3. 파일 예측·6건 이상 직접 입력의 지시문이 JSON에 없는 map_check를 알리라고 함 (재현, 중간)
- 위치: `ml_predict.py:1569-1570` (조건이 `map_check_keys`), `1367-1372` (`map_check`는 직접 입력 5건 이하일 때만)
- 재현: `--model para.xlsx --file new100.xlsx` 또는 `--input in7.json`(7건) -> 지시문에 "예측값마다 실측 비교값(map_check의 value, diff, method)을
  '실측 비교값'으로 함께 알리세요". JSON에는 `map_check_keys`, `map_check_outside_interval`만 있습니다. 없는 키를 알리라고 하면 경량 모델이 값을 지어냅니다.
- 고칠 방향: 결과 파일이 있을 때는 "실측 비교값은 결과 파일의 map_ 열" 한 마디로 바꾼다.

#### B4. 숫자 입력에 범위(`150:210:10`)를 줬을 때의 안내가 거절되는 사용법을 가르침 (재현, 중간~낮음)
- 위치: `ml_predict.py:465` (안내: `--vary "<입력>" --sweep "<시작>:<끝>:<간격>"`), `2751` (그 사용법을 인자 오류로 거절)
- 재현: `--input "온도=150:210:10,압력=3,라인=A"` -> 안내대로 `--vary 온도 --sweep "150:210:10" --input "압력=3,라인=A"` 실행 -> exit 2
  "--vary를 빼십시오" (`[추천]` 없음). 두 번 멈추고 경량 모델이 명령을 스스로 조합해야 합니다.

  2751행도 고친 전체 명령을 `[추천]`.

#### B5. ml_map: 값이 하나뿐인 기준 열을 함께 주면 qhull 오류 글이 message에 그대로 (재현, 중간~낮음)

  글자 열로 거른 뒤 한 기준이 한 값만 남는 표에서 흔히 생깁니다. 사용자에게 그대로 전달되고, 무엇을 고칠지 알 수 없습니다.

#### B6. --find 고정 입력 `inf`는 내부 오류 (재현, 낮음)

#### C4. 파일 예측 결과 파일에 행별 표시가 없음 (재현, 중간~낮음)

### 2. 계약 위반 / 내부 오류 / 실행할 수 없는 안내

#### B1. 보고서 명령이 시간 제한에 닿으면 Word 보고서 없이 `status: ok` + "다시 실행하지 마세요" (재현, 높음)

  "UNVERIFIED: 성능예측표 ... 저장됨, 확인하지 못함 ... 같은 명령을 다시 실행하지 마세요"다. 사용자는 보고서를 요청했는데 보고서는 만들어지지 않았고,

- 고칠 방향: (a) 보고서를 먼저 저장하고 성능예측표를 나중에 만들거나, (b) 보고서 명령 안에서는 성능예측표를 `rerun_safe`로 표시하고 다시 실행 때
  이미 만든 xlsx를 재사용, (c) 적어도 `committed_payload`에 "Word 보고서는 만들지 못함"과 보고서만 만드는 전체 명령을 `next_commands`로 준다.

- 확신: 높음 (모두 생성된 docx에서 확인).

#### D5. 파생변수 수식의 엑셀 쪽은 엑셀이 없으면 한 번도 계산되지 않는데 preview는 "모델과 같은 계산 (조건 N개 확인)" (코드 + 추정 70%, 낮음)
- 위치: `ml_export.py:284-289` (`model_features`: 파생변수를 파이썬 `apply_inference_evals`로 계산), `334-357` (`excel_expr`), `1108-1110`
- 내용: "조건 2,200개 확인"은 잎·계수의 파이썬 사본만 본다. 파생변수의 엑셀 수식(`excel_expr`의 결과)은 그 확인에 들어가지 않고, 엑셀이 있는 PC의 50개 조건으로만 본다.
  읽어서 찾은 차이 후보: 음수 밑의 분수 지수. 파이썬은 `(-8) ** (1/3)` = NaN -> 학습 중앙값인데 엑셀은 `(-8)^(1/3)` = -2를 낸다 (추정 70%, 엑셀 실행 못 함).
  `0 ** 0`도 파이썬 1, 엑셀 `#NUM!` -> 중앙값. 직접 확인한 것: `a / b`(0 나누기), `a ** 0.5`(음수), `a % 2`, `a // 2`, `log(a)`, `c ** 2`는 수식을 손으로 계산해
  `ml_predict.py --input` 값과 4개 조건에서 일치 (5장).
- 방향: 파생변수 수식에 대한 작은 파이썬 평가기(지원 함수만)로 무작위 조건을 비교하거나, 음수 밑 `^`는 `IF(밑<0, 오류, ...)`로 감싼다.
- 확신: 구조는 코드로 확실, 엑셀 값 차이는 추정 70%.

#### D6. 그 밖 (코드/재현, 낮음)
- 모델은 빈 입력을 중앙값으로 채워 예측하지만(학습 데이터에 빈 칸이 있던 입력 포함) 계산기는 입력이 하나라도 비면 예측을 내지 않는다
  (`ml_export.py:611`, 재현: 압력에 빈 칸 17개인 데이터). 안전한 쪽이지만 "모델 예측과 같다"는 설명과 다르므로 사용법 시트에 한 줄이 필요하다.
- `ml_dataset.py --reason "=고온" --save u.xlsx`: 이유가 수식으로 저장돼 다시 읽으면 0이 된다. 도구가 `UNVERIFIED`("다시 읽은 값이 기대값과 다름")로 잡아내지만
  원인을 알려 주지 않는다 (재현). `=`, `+`, `-`, `@`로 시작하는 이유는 저장 전에 거절하거나 글자로 쓰게 한다.
- 보고서를 다시 만들 때마다 성능예측표(수 MB)가 시각 붙은 새 이름으로 하나씩 더 생긴다 (재현, `recovered`로 알림). 문장만 바꿔 보고서를 다시 만드는 흐름에서
  폴더에 같은 내용의 xlsx가 쌓인다. 버전 폴더가 그대로면 기존 성능예측표를 재사용하는 편이 낫다.

### 5. 확인했고 문제를 찾지 못한 것

- **나무 모델을 옮긴 값**: 저장된 xlsx의 숨김 시트에서 잎 범위·잎 값을 openpyxl로 읽어 `SUMPRODUCT`와 같은 계산(하한 초과, 상한 이하)을 따로 하고
  모델 예측과 비교했다. 조건은 갈림 경계값 그 자체, 바로 다음/이전 double, 경계값 x (1+1e-13), 범위 밖(+-1e6, +-1e12, 0)을 입력마다 최대 300개 경계에서.
  ExtraTrees 3개(7,205 / 7,205 / 6,005 조건), HistGradientBoosting(1,697), RandomForest(2,417, 값이 하나뿐인 입력과 빈 칸 포함 데이터),
  파생변수를 쓰는 ExtraTrees(8,405) 모두 최대 차이 2e-13 이하, 조건마다 나무당 잎이 정확히 하나. 파일의 잎 값은 repr 전체 자리로 저장됨.
- **선형 모델·파생변수 수식**: 계산기 수식을 손으로 옮겨 계산한 값이 `ml_predict.py --input` 예측과 4개 조건(0 나누기, 음수 제곱근 포함)에서 4자리까지 일치.
  90% 범위 상수도 예측 도구의 범위와 일치.
- **stdout 1줄 JSON**: ml_report, ml_export, ml_dataset의 성공/실패/`-h`/인자 오류/시간 제한 약 60회 실행 모두 1줄. exit 코드 0/1/2 계약대로.
- **시간 제한(저장 전)**: 저장 전에 닿으면 `STOP_RETRY` + `[추천] <같은 명령> --time-limit 570`(그대로 실행 가능한 전체 명령).
- **덮어쓰기**: 보고서·성능예측표·데이터셋 모두 기존 파일을 덮어쓰지 않고 시각 붙은 이름 + `recovered`. 원본과 같은 `--save`는 거절.
- **특수 문자 이름**: `수율(1차) [%]`, `손실:율?<kW>`, `O'Brien 값`, `"따옴표"`, `a=b`, `x*y`, `유속 (m/s)` 열로 학습 -> 보고서·성능예측표 생성, 시트 이름 겹침 없음,
  수식의 시트 참조 정상 (계산식 표의 표기만 A3).
- **분류 보고서**: 2클래스·3클래스(`C급(재작업)`) 모두 생성, 표의 숫자가 leaderboard.json과 일치. 분류 버전에 `ml_export.py`는 한국어 `STOP_RETRY`.
- **적은 행(12행), 값이 하나뿐인 입력, 빈 칸이 있는 입력**: 오류 없이 생성, 값이 하나뿐인 입력은 `warnings`.
- **ml_dataset**: 빈 행이 낀 엑셀의 `--rows` 행 번호, 앞자리 0 코드(`코드 = 7` -> 표기 다름 `warnings` + 전체 명령 `[추천]`), `50%`·`1,500`·날짜 조건,
  띄어쓰기 있는 값, 0행(`count: 0`, 파일 없음), 이미 표시된 행 유지, 저장 뒤 다시 읽기 비교, 만든 파일로 학습했을 때 제외 행 수가 맞는 것까지 확인.
