## (1) 결정이 필요한 설계 변경

### 1-1. A영역 C1: 성능 개선 루프가 같은 입력을 거듭 곱한 교차항을 쌓는다
- 무엇이 문제인가: 관계가 약한 60행 데이터에서 `next_commands[0]`을 따라가면 v2~v10까지 `반응온도x압력` -> `반응온도x반응온도x압력` -> ... 을 계속 더하고,
  검증 R2가 0.137 -> 0.200으로 조금씩 올라 대부분 "최고 성능"으로 보고합니다. 같은 60행으로 10번 고른 것이라 그 점수는 잡음입니다.
- 선택지:
  1. 고친다: 교차항은 원본 입력끼리만(파생변수는 재료에서 제외), 같은 쌍은 1번, 개선이 0.01 미만이면 "나아지지 않음"으로 셈, 전체 회차 상한(예: 5회).
  2. 교차항 자동 제안을 없앤다 (약한 입력 빼기 제안만 남김).
  3. 그대로 둔다.
- 추천안: 1. 300행 이하에서는 R2 0.01 차이는 fold 나누기만 바꿔도 생기는 크기라 "개선"으로 세면 안 됩니다. 2도 단순해서 나쁘지 않지만,
  교차항 1번은 실제로 도움이 되는 경우(온도x압력)가 있어 1번만 허용하는 쪽이 낫다고 봅니다.
- 난이도: 3~4시간 (후보 규칙 + 멈춤 조건 + 테스트).
- 위험: 문턱 0.01은 근거가 약한 어림값입니다. 진짜로 조금씩 나아지는 데이터에서 일찍 멈출 수 있습니다 (멈춰도 사용자가 직접 `--eval`을 줄 수는 있음).
  "fold 표준편차 이내" 기준은 더 정확하지만 설명이 어려워 0.01 고정을 권합니다.
- 지금 상태: 고치지 않음. `ml_train.py` 1768~1778행이 상위 숫자 입력 2개의 곱을 제안하며, 상위 입력이 파생변수여도 그대로 곱합니다.
  멈춤은 "최근 5번이 이전 최고를 0.0001도 못 넘을 때"뿐입니다 (`IMPROVE_ROUNDS = 5`).

### 1-2. A영역 C5: 입력 열의 극단값도 자동 이상치로 학습에서 빠진다
- 무엇이 문제인가: 30행 중 일부러 넣은 고농도 조건 2행(`첨가제` 2.0, 나머지 0.5~0.6)이 `자동 이상치: 첨가제`로 빠집니다.
  실험계획 데이터에서는 그 2행이 가장 정보가 많은 행이고, 빠지면 그 조건의 예측은 외삽이 됩니다.
- 선택지:
  1. 타겟 기준 이상치만 자동 제외. 입력 극단값은 빼지 않고 warnings로 "드문 조건 N행"만 알림.
  2. 수정자 제안: 타겟 이상치 + 입력은 아주 심한 값(robust z > 10, 입력 오타 수준)만 자동 제외, 나머지는 warnings.
  3. 그대로 (타겟·입력 모두 z > 3.5면 제외, 전체의 10%를 넘으면 제외 안 함).
- 추천안: 2. 소수점 빠뜨린 값(18.5를 185로) 같은 입력 오타는 걸러 주면서 의도한 조건은 남깁니다. 다만 규칙이 하나 더 생기므로,
  단순함을 더 중시하면 1도 괜찮습니다 (입력 오타는 warnings를 보고 사용자가 `제외` 열에 표시).
- 난이도: 3~4시간 (preview에서 "타겟 이상치"와 "입력 값이 드문 조건"을 구분하는 문구 포함).
- 위험: 입력 오타 행이 학습에 남아 모델이 나빠질 수 있음(선택지 1에서 더 큼). z > 10이라는 숫자도 어림값입니다.
  기존 학습 결과와 제외 행이 달라지므로 같은 데이터의 점수가 바뀝니다 (베타라 문제는 아님).
- 지금 상태: 고치지 않음. `OUTLIER_Z = 3.5`를 타겟과 숫자 입력 전부에 적용합니다. preview에 제외 행과 이유, "제외 행 포함" 점수는 나옵니다.

### 1-3. A영역 A2 나머지: 합계·평균 행을 학습에서 자동으로 뺄지
- 무엇이 문제인가: 표 맨 아래 `합계`, `평균` 행. 수정으로 "합계 행 때문에 모든 숫자 열이 타겟 누수로 빠지는" 결함은 없어졌지만, 그 행 자체를
  학습에서 빼지는 않습니다. 합계 행은 대개 이상치로 우연히 빠지고, 평균 행은 평범한 값이라 학습 데이터로 들어갑니다 (40행에 가짜 1행).
- 선택지:
  1. 첫 열 등에 `합계`/`평균`/`계`/`Total` 같은 글자가 적힌 행만 자동 제외하고 preview와 warnings에 행 번호를 알림.
  2. 자동 제외하지 않고 지금처럼 경고만, 사용자가 `제외` 열에 직접 표시.
  3. 글자가 없어도 숫자가 합계와 맞으면 제외 (숫자만 있는 합계 행).
- 추천안: 1. 글자로 `합계`라고 적힌 행이 측정값일 가능성은 거의 없어 "원인이 분명하고 뜻이 바뀌지 않는" 경우입니다.
  3은 우연히 맞는 행을 뺄 수 있어 권하지 않습니다 (데이터를 건드리는 추측).
- 난이도: 2~3시간.
- 위험: 범주 값이 실제로 `평균`, `계`인 데이터에서 잘못 뺄 수 있습니다 (드묾, 알림에 행 번호가 나오므로 사용자가 알 수 있음).
- 지금 상태: 합계 행은 판정해서 경고하고 입력 진단(누수·ID·상수)에서만 뺍니다. 학습에서는 빼지 않습니다 (수정자가 일부러 안 함).
  평균 행 1행이 300행 이하 데이터의 점수에 주는 영향은 작을 것으로 추정합니다 (재어 보지 않음).

### 1-5. C영역 C3: 엑셀 다시 계산 확인 1%의 기준
- 무엇이 문제인가: 지금 1%는 "예측값 크기" 기준입니다. 타겟이 1000 근처에서 990~1010만 움직이면 엑셀 값이 10(움직이는 폭의 절반) 틀려도
  1% 안이라 통과하고, 예측값이 0 근처인 타겟은 아주 작은 차이로 실패(UNVERIFIED)합니다.
- 선택지:
  1. 허용 = 그 타겟 예측 범위(확인한 조건들의 최대-최소)의 1%. "99% 일치"라는 결정의 뜻은 그대로.
  2. 허용 = max(예측값의 1%, 범위의 1%) 가운데 작은 쪽/큰 쪽을 섞는 식.
  3. 그대로 (예측값의 1%).
- 추천안: 1. 사용자가 말한 "99% 일치"는 "쓸 만큼 같다"는 뜻이고, 쓸 만한지는 타겟이 움직이는 폭에 견줘야 맞습니다. 0 근처 타겟의 헛실패도 함께 없어집니다.
- 난이도: 1시간 (`compare_excel` 한 줄 + 테스트).
- 위험: 값이 큰 타겟에서는 지금보다 엄격해져 예전에 통과하던 파일이 UNVERIFIED가 될 수 있습니다. 확인 조건이 50개 안팎이라
  범위가 0에 가까운 경우(모든 조건의 예측이 같음)는 따로 처리해야 합니다. 엑셀이 실제로 1% 가까이 다른 값을 내는 일 자체가 드물 것으로 추정합니다
  (검토 환경에 엑셀이 없어 실행 못 함).
- 지금 상태: `ml_export.py` `EXCEL_TOL = 0.01`, `rel = diff / max(abs(w), 1e-12)` (예측값 크기 기준). 고치지 않음.

### 1-6. C영역: `--save` 상대 경로의 기준이 도구마다 다르다
- 무엇이 문제인가: `--save out.docx`처럼 폴더 없이 주면 저장 위치가 도구마다 다릅니다. 수정 뒤에도 ml_report와 ml_export는 `<데이터>_ml_data` 폴더,
  ml_dataset은 원본 데이터 옆입니다. 게다가 도구가 내는 `[추천]`/`next_commands`는 공통 함수(`command_text`)가 상대 `--save`를
  "현재 폴더" 기준 절대 경로로 바꾸므로, 추천 명령을 실행하면 처음 명령과 다른 곳에 저장될 수 있습니다.

- 위험: 1에서는 경량 모델이 warnings를 전하지 않으면 사용자가 "20행만 학습됨"을 모를 수 있습니다. preview에도 시트 이름이 들어가는지는 확인 못 함

### 3-2. A영역 A4: 입력 자동 선택의 문턱
- 무엇이 문제였나: 상관 0.98 이상이면 "타겟 누수"로 빼서 검량선 같은 진짜 예측 변수가 빠졌고, 1씩 늘어나는 정수 열(`경과일` 1~30)은 무조건 ID로 뺐습니다.
- 지금 상태: 누수 자동 제외는 |상관| 0.999 이상(또는 이름이 같고 단위만 다른 열은 0.9 이상). 0.98~0.999는 입력으로 두고 "타겟과 상관 매우 높음" 경고.
  1씩 늘어나는 정수 열은 타겟과의 관계가 0.3 이상이면 입력으로 두고 경고, 아니면 ID로 제외. 뺀 열을 다시 넣는 전체 명령을 `confirm_commands`로 줍니다.
  타겟이 여럿일 때 한 타겟에만 누수여도 모든 타겟에서 빠지는 것은 그대로이고, 이유 문구에 "타겟을 나눠 학습"이 들어갑니다.
- 선택지: 1. 그대로. 2. 누수 문턱을 검토 제안값 0.9999로 올린다. 3. 자동 제외를 없애고 전부 경고만.
- 추천안: 1. 다만 솔직히 0.999와 0.9999 중 어느 쪽이 맞는지는 데이터에 달려 있어 확신이 없습니다. 잡음이 아주 작은 검량선(상관 0.9995)은 지금도 빠집니다.
  빠져도 preview에 나오고 다시 넣는 명령이 있으므로 받아들일 만합니다. 실기에서 잘못 빠지는 사례가 나오면 0.9999로 올리면 됩니다 (상수 하나).
- 위험: 문턱을 올릴수록 "타겟을 단위만 바꿔 반올림해 적은 열"(상관 0.9997쯤)이 입력으로 들어가 R2 1.0짜리 쓸모없는 모델이 될 수 있습니다.
  그때는 "상관 매우 높음" 경고만이 방어선입니다. 0.3이라는 ID 문턱도 어림값입니다 (30행에서는 무관한 번호 열도 우연히 0.3을 넘을 수 있음: 그러면 입력으로 남고 경고).
- 난이도: 숫자만 바꾸면 30분.

### 3-3. A영역 A6: 단위를 붙여 적은 숫자 열 (`187.3℃`, `2.45 bar`, `1,873원`)
- 무엇이 문제였나: 이런 열이 값 종류 38개의 범주 열로 학습되어 R2 -0.015인 모델이 VERIFIED로 나왔습니다.
- 지금 상태 (수정자의 선택): 칸의 90% 이상이 `<숫자><같은 단위>` 모양인 열이 있으면 학습을 멈추고 "숫자에 단위가 붙음"을 알립니다. 단위를 떼고 읽지는 않습니다.
- 선택지: 1. 그대로 멈추고 사용자에게 엑셀에서 단위를 지우라고 알림. 2. 도구가 단위를 떼고 숫자로 읽고 warnings에 "단위 '℃'를 떼고 읽음".
- 추천안: 1. 오늘 결정("도구가 못 하는 것은 사용자에게 직접 하라고 알린다")과 맞고, `12호기`, `3A` 같은 코드를 숫자로 잘못 읽을 위험이 없습니다.
  2를 하려면 예측(`--input 온도=180℃`, 지금은 거절)과 파일 예측도 같은 함수로 맞춰야 해서 규칙이 늘어납니다.
- 위험: 1에서는 사용자가 엑셀에서 열 전체의 단위를 지워야 합니다 (찾아 바꾸기로 1분, 다만 귀찮음). 멈춤 문구가 "엑셀에서 무엇을 하라"까지
  말하는지는 문구를 읽지 못해 확인 못 함 (모자라면 문구만 보강, 30분).
- 난이도: 2로 바꾸면 반나절 (학습·예측 공통 + 테스트).

### 3-4. B영역 A2: ml_map에서 기준 열을 일부만 주면 멈춘다
- 무엇이 문제였나: 온도 x 압력 격자 표에 `--input "온도=175"`만 주면 압력 1~3 전체를 평균한 31을 VERIFIED로 냈습니다 (라인 A/B 표도 두 라인 평균).
- 지금 상태: 계산하지 않고 멈춥니다(`needs_user_decision`). "기준으로 주지 않은 열 '압력'이 있어 계산하지 않았습니다 ... (표의 값: ...)" + `missing_keys` +
  `next_commands[0]`에 `--input '온도=175,압력=<값>'` 틀(`needs_input: true`). 사용자에게 값을 물은 뒤 `<값>`을 바꿔 실행하라고 합니다.
- 선택지: 1. 그대로. 2. 멈추지 않고 평균값을 내되 UNVERIFIED + 경고. 3. 빠진 열이 글자 열이고 종류가 적으면 종류별 [후보] + 전체 명령을 줌(숫자 열은 1처럼).
- 추천안: 1. 평균값은 뜻이 없는 숫자라 내지 않는 것이 맞습니다. 3은 더 친절하지만 규칙이 갈립니다.
- 위험: `<값>`을 경량 모델이 직접 바꿔 넣어야 합니다. AGENTS.md "값만 주어 LLM이 명령에 끼워 넣게 하지 않는다"와 긴장이 있지만, 숫자 값은 도구가 대신 고를 수 없고
  ml_predict의 예측 틀이 이미 같은 방식(`needs_input`)입니다. 경량 모델이 `<값>`을 그대로 둔 채 실행하면 "숫자가 아님"으로 다시 멈춥니다 (틀린 답은 안 나옴).
  "모든 압력의 평균"을 정말 원한 사용자는 이제 방법이 없습니다 (드묾).
- 난이도: -

### 3-5. B영역 A7: `--find` 외삽 답의 한도 30%
- 무엇이 문제였나: 표의 A가 0~100인데 `--find "B=5000" --vary A`가 `A: 305 [외삽]`(실제 223.6)을 VERIFIED 답으로 냈습니다.
- 지금 상태: 답이 데이터 범위에서 데이터 폭의 30%보다 멀면 답으로 주지 않고(`FAR_FIND = 0.3`) 경고와 도달 가능한 범위를 알립니다. 30% 안의 외삽 답은 `[외삽]` 표시와 함께 줍니다.
  한 건 사잇값(`--input`)의 외삽에는 한도가 없습니다 (범위 밖이면 직선 연장 값 + 외삽 표시·경고).
- 선택지: 1. 그대로 30%. 2. 더 엄격하게 (0%: 범위 밖 답은 주지 않음, 또는 10~20%). 3. 한 건 사잇값에도 같은 30% 한도를 둠.
- 추천안: 1 + 3. 30%는 검토가 예로 든 20~30%의 위쪽 값이고 근거가 있는 숫자는 아닙니다. 곡선이 심한 표에서는 30% 밖도 꽤 틀릴 수 있지만 `[외삽]`이 붙으므로 받아들일 만합니다.
  한 건 사잇값만 한도가 없는 것은 "같은 일은 같은 규칙"에 어긋나므로 맞추기를 권합니다 (온도 0~100 표에 `온도=500`을 주면 지금은 값이 나옴).
- 위험: 한도를 두면 "조금 벗어난 값이라도 알고 싶다"는 사용자가 답을 못 받습니다 (도달 가능한 범위는 알려 줌).
- 난이도: 3을 넣으면 1~2시간. 숫자만 바꾸면 10분.
